# BillFlow Suite — PDF Document Suite Technical Guide

This document describes the architecture, statutory compliance framework, design tokens, and verification lifecycle for all printable billing-side documents generated by BillFlow Suite.

---

## 1. Executive Summary & Design Vision

BillFlow Suite delivers an enterprise-grade document generation engine engineered in Python with ReportLab. Every printable commercial and statutory document has been completely redesigned to meet two non-negotiable standards:

1. **Statutory Integrity:** Strict adherence to the Central Goods and Services Tax Act, 2017 (CGST Rules 2017):
   - **Tax Invoices:** Full compliance with **Rule 46 CGST Rules 2017** (7-row supply reference grid, recipient billing/shipping breakdown, state codes, HSN summary, and triplicate copy designations).
   - **Delivery Challans:** Full compliance with **Rule 55 CGST Rules 2017** (mandatory 5-clause statutory delivery declaration, transporter IDs, vehicle numbers, E-way Bill citation).
   - **Credit & Debit Notes:** Full compliance with **Rule 53 CGST Rules 2017** (original tax invoice cross-reference, date of original supply, GSTIN of recipient).
   - **Commercial Documents:** Standard commercial terms, validity windows, delivery milestones, and payment instructions on Quotations, Proforma Invoices, Purchase Orders, and Payment Receipts.

2. **Full-Page Geometric Excellence:**
   - **Zero Bottom Blank Band:** On single-page documents, content dynamically expands via calculated filler table rows to fill the full A4 canvas. Content lowest point terminates at $\le 12\text{ mm}$ from the paper bottom.
   - **Print Margin Frame:** All elements stay strictly $\ge 8\text{ mm}$ within printable physical edges to avoid thermal or laser printer clipping.
   - **Visual Distinction:** Every document type possesses its own dedicated, bespoke visual personality (distinct brand accent, typography weight, table header styling, and reference grid hierarchy), preventing the "generic template" look.

## 2. Architecture & Engine Pipeline

The PDF suite is architected around absolute isolation between document templates, supported by robust core primitives:

```
app/services/pdf/
├── core/                       # Shared foundational engine (ONLY allowed shared code)
│   ├── page.py                 # BillFlowDocTemplate & NumberedCanvas
│   ├── flex_table.py           # Dynamic filler height calculation engine
│   ├── formatting.py           # INR & International currency, date formats, words
│   ├── fonts.py                # TTF font registration, Rupee symbol fallback
│   ├── images.py               # Non-crashing safe image loader with aspect ratio
│   ├── stamps.py               # Vector watermark stamps (DRAFT, CANCELLED, etc.)
│   └── text.py                 # Safe make_p Paragraph wrapper
└── templates/                  # 8 Dedicated, isolated templates (NEVER import each other)
    ├── tax_invoice.py          # Rule 46 CGST Tax Invoice (Triplicate support)
    ├── proforma.py             # Commercial Proforma Invoice
    ├── quotation.py            # Sales Quotation / Commercial Offer
    ├── delivery_challan.py     # Rule 55 CGST Goods Movement Challan
    ├── credit_note.py          # Rule 53 CGST Credit Note
    ├── debit_note.py           # Rule 53 CGST Debit Note
    ├── purchase_order.py       # B2B Procurement Purchase Order
    └── payment_receipt.py      # Dual-Card Cash & Bank Payment Receipt
```

### Core Primitives

#### 1. `BillFlowDocTemplate` (`app/services/pdf/core/page.py`)
Standard ReportLab `SimpleDocTemplate` initializes its default `Frame` with `topPadding=6, bottomPadding=6, leftPadding=6, rightPadding=6`, stealing 12 points vertically and throwing off exact printable boundary computations. `BillFlowDocTemplate` subclasses `SimpleDocTemplate` and zeroes all frame paddings (`padding=0`), delegating exact spacing to layout flowables.

#### 2. `NumberedCanvas` (`app/services/pdf/core/page.py`)
A two-pass canvas accumulator that records total page counts and draws:
- Outer border frame (`0.75 pt` line, rounded corners).
- Footer text placed at `FRAME_Y + 4 pt` (~`11.4 mm` from bottom edge). The lowest text descender sits safely at $\approx 10.86\text{ mm}$ from page edge, fully satisfying the requirement ($\le 12\text{ mm}$ from bottom, $\ge 8\text{ mm}$ within frame).
- Page numbers formatted as `"Page X of Y"`.
- Application signature `"Generated by BillFlow Suite • Enterprise Edition"`.

#### 3. Dynamic Filler Engine (`app/services/pdf/core/flex_table.py`)
To prevent the unsightly "half-empty bottom gap" on short invoices, `calculate_filler_height` dynamically measures the exact heights of all flowables preceding the item table, the items themselves, and the closing blocks (totals, bank info, terms, declarations, and signatures). If the remaining printable vertical space on Page 1 is between `15 pt` and `250 pt`, it creates a filler row with a `4.5 pt` safety buffer that absorbs the gap perfectly without causing an accidental second page.

#### 4. Safe Image Loader (`app/services/pdf/core/images.py`)
Guarantees that missing, corrupt, truncated, or excessively large company logos, official seals, and signatures never crash document generation. Images are loaded with PIL, validated, scaled proportionally within maximum bounding boxes, and gracefully omitted if invalid.

## 4. Statutory Parity & Reference Defect Resolution

During initial analysis of legacy templates and reference documents (`docs/reference/12-signed.pdf`), 5 critical defects were identified and resolved across the suite:

1. **Defect 1: Hardcoded / Monolithic Tax Labels**
   - *Legacy Issue:* Fixed `CGST 9% / SGST 9%` lines caused invalid outputs for intra-state 12% / 28% items or inter-state supplies requiring IGST.
   - *Suite Solution:* Dynamic tax calculation engine automatically computes and presents distinct multi-slab CGST + SGST or IGST rows based on actual item tax rates and supply state codes.
2. **Defect 2: Bottom Blank Gap on Short Documents**
   - *Legacy Issue:* Short 1-item invoices terminated midway down the page, leaving up to 100 mm of empty white space.
   - *Suite Solution:* `calculate_filler_height` dynamically measures preceding flowables and inserts a proportional filler row with a `4.5 pt` safety buffer, ensuring the document terminates precisely $\le 12\text{ mm}$ from page bottom.
3. **Defect 3: ReportLab SimpleDocTemplate Frame Padding Clipping**
   - *Legacy Issue:* Default `6 pt` top/bottom frame padding subtracted `12 pt` vertically, misaligning footer measurements.
   - *Suite Solution:* `BillFlowDocTemplate` zeroes frame padding (`leftPadding=0, rightPadding=0, topPadding=0, bottomPadding=0`).
4. **Defect 4: Currency Symbol Fallback & Numbering Precision**
   - *Legacy Issue:* Missing glyphs or raw `?` characters rendered when printing Unicode Rupee symbols (`₹`) in standard fonts.
   - *Suite Solution:* `fonts.py` registers Unicode fonts with graceful `Rs.` fallback when custom fonts are absent. Number formatting supports both Indian (`₹ 1,23,456.78`) and International (`₹ 123,456.78`) grouping.
5. **Defect 5: Missing Mandatory Rule 46 / Rule 55 CGST Disclosures**
   - *Legacy Issue:* Missing supply reference grids (e.g., place of supply state code, reverse charge applicability, transportation mode).
   - *Suite Solution:* 7-row supply reference grid on all invoices and 5-clause statutory movement declaration on delivery challans.

## 5. Geometric Standards & Dimensions

All documents are designed for standard ISO A4 paper:
- **Sheet Dimensions:** `210 mm × 297 mm` (`595.27 pt × 841.89 pt`).
- **Outer Margin:** `28.35 pt` (`10.0 mm`) on all 4 sides.
- **Outer Frame Border:** `0.75 pt` line width, `4 pt` corner radius.
- **Total Printable Width:** `538.57 pt` (`190.0 mm`).
- **Footer Baseline:** Sits at `FRAME_Y + 4 pt` (`32.35 pt` / `11.41 mm`), with text descenders at `~10.86 mm` from page bottom.
- **Pagination Limit:** Single-page 1-item documents terminate between `10.8 mm` and `11.8 mm` from page bottom, strictly satisfying the $\le 12\text{ mm}$ rule while remaining safely inside the $\ge 8\text{ mm}$ printer frame boundary.

## 6. Document Suite Configuration UI

The PDF suite settings are fully integrated into **Settings & Preferences** (`app/ui/views/settings_view.py`) under the **Company Profile & Print Settings** tab (`📄 PDF Document Suite & Print Settings` sub-tab):

- **Official Seal Image Picker:** Upload and preview company seal/stamp (PNG/JPG $\le 2\text{ MB}$, auto-scaled).
- **Authorised Signatory Signature Picker:** Upload and preview authorized signature asset.
- **Currency & Number Format:** Toggle between Indian numbering (`1,23,456.78`) and International numbering (`123,456.78`).
- **Triplicate Printing:** Option to print three copies for tax invoices (`ORIGINAL`, `DUPLICATE`, `TRIPLICATE`).
- **HSN Breakdown Summary:** Toggle comprehensive HSN/SAC tax breakdown table.
- **Challan Valuation:** Toggle display of unit prices and item totals on Delivery Challans.
- **Per-Document Terms & Legal Declarations:** Live text editors for custom tax declarations, quotation terms, PO terms, and delivery challan notes.

## 7. Verification & Quality Assurance Lifecycle

The PDF suite includes automated test suites and sample generation scripts:

### Running Test Suites
```bash
# 1. Run all layout geometry, filler, and boundary tests (25 tests)
pytest tests/test_pdf_layout_all_documents.py

# 2. Run AST isolation, Hamming distance, and 150-item benchmark tests (11 tests)
pytest tests/test_pdf_document_suite.py

# 3. Run full accounting and billing integration test suite (38 tests)
python tests/test_full_qa_suite.py
```

### Generating All 120 Visual Samples & Edge Scenarios
```bash
python scripts/build_all_samples.py
```
This script generates **120 document PDFs** and high-resolution rasterized PNG previews in `docs/pdf_samples/` across all 8 document types and 15 edge scenarios:
- `single_item`: 1 item testing dynamic filler table expansion.
- `five_items`: Mid-size standard document.
- `ten_items`: Full page with multiple items.
- `multipage_30`: Multi-page pagination test.
- `benchmark_150`: 150 items stress test (benchmarked at $< 5.0\text{ seconds}$).
- `zero_tax`: 0% GST / Exempt supplies.
- `high_gst_28`: 28% luxury / cess rate.
- `interstate_igst`: Inter-state supply across state lines.
- `discount_100_percent`: Free commercial sample / promotional items.
- `decimal_quantities`: High-precision fractions (e.g. 3.750 KG).
- `long_descriptions`: Long multi-line wrapping text.
- `empty_party_details`: Graceful handling of legacy records with missing metadata.
- `cancelled_watermark`: Watermark rendering test.
- `signature_and_seal`: Branding image integration test.
- `unicode_and_symbols`: Multi-lingual and Rupee symbol verification.
